# MCP 效率改造与测试报告 · 2026-09-12

已完成本地实现和验收，未向 GitHub 推送，未删除分支。修改前检查点：071 `9b6d1e9`；Cloud `6ce8fb7`（保存当时已有改动）。

## 改动与功能边界

- 外部工具 22 → 19；常用 6 个入口。合并截图与 inbox，完整功能仍可调用。内置 Agent 暴露当前文档的 13 个工具。
- 支持客户端原生按需加载；服务端仍返回完整的简短 schema。ZCode 实测加载全部 19 个，没有宣称它只加载 6 个，也没有新增“先搜索工具”这一必经往返。
- 源码补丁改为一次浏览器 RPC：验证当前源码哈希 → 严格 diff → 保存 Undo → 返回新哈希。支持最终写入同时截图与 completion。
- 完成回执只有写入、所请求截图均成功后才发出；截图失败保留 applied，不重复写入。排队旧进度不会覆盖 done。
- 默认简短回执，保留对象、源码路径、正确的 contentHash、实际 viewport 和错误。内部另一种 Widget 哈希不再出现在默认回执中，避免被误用作下次源码补丁哈希。
- HTTPS 复用：4 sockets，最多 2 条空闲连接，客户端空闲 25 秒、服务端 keep-alive 30 秒。认证、CA 校验和访问范围未删减。
- 普通请求最多 4 个并行，同文档按序；初始化/新会话有序。取消有独立有界通道，处理异步等待期间的取消。浏览器的共享写入队列仍保留，不能把此改动解读为同一浏览器内所有写操作并行。

## 真实耗时

同机、同一场景、分别运行修改前后服务；每组 20 次顺序源码补丁。已核对最终源码与哈希。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 补丁耗时中位数 | 8.68 ms | 6.63 ms |
| 补丁 p95 | 10.89 ms | 8.01 ms |
| 创建并截图，单次样本 | 107.32 ms | 81.69 ms |
| 补丁的浏览器 RPC | 2 | 1 |

这组本地热路径补丁中位数约缩短 **24% / 2.05 ms**。创建截图仅单样本，不据此承诺百分比。该数据不含模型推理，不是公网或所有设备性能承诺。

实际更大的机会是减少模型循环：最终 ZCode 场景只用了 4 次工具调用，最终补丁不再额外调用截图及状态工具。

## 拖动、缩放后是否能 patch

**已真实复现问题并修复，再通过 Computer Use 验证。**

原因：Widget 在拖动/缩放结束后仍保留选中编辑状态 `widgetEdit`。文档入口先调用通用 `canvasAgentMutationIdle`，把该状态当作忙，返回 `CANVAS_BUSY`；底层原本可保留几何的 source-only 提交逻辑没有机会执行。

修复：Widget 源码直接走 source-only 提交路径，移除原有 1.5 秒手势等待及 BUSY 拒绝。正在拖动/缩放也立即更新，保留当前几何和手势对象；几何变化和源码变化分别进入 Undo，不消耗其他正在进行的笔迹、图片、文本编辑记录。新增自动测试验证手势未结束时提交、继续移回起点、取消几何后源码仍保留。真正的源码变化仍返回 `SOURCE_CONFLICT`；几何文件的编辑仍受几何安全检查保护。

实际顺序：读取源码及哈希 → 用鼠标拖动 → 用鼠标缩小 → 保持选中 → 用原哈希 patch A→B，并同时截图和 done。

| 几何 | 原值 | 用户操作后 | patch 后 |
|---|---:|---:|---:|
| x | 1000 | 966.412214 | 966.412214 |
| y | 1000 | 1036.946565 | 1036.946565 |
| w | 1400 | 1092.977099 | 1092.977099 |
| h | 880 | 687.014177 | 687.014177 |

逐字段完全一致，延迟重新读取后仍一致。没有重新读取源码或替换旧哈希；一次返回 applied、截图和完成回执。内置 Agent 生成的另一张 Widget 也实测 Undo 到 A、Redo 回 B。

## 真实模型与界面测试

使用本机 ZCode 3.11.2 自带 CLI 0.16.5。日志核实实际模型为 `deepseek-v4.1-flash-expires-on-0910`，请求发往 `https://api.deepseek.com/v1`；模型名字中的到期日期没有阻止本次调用。

最终外部 ZCode：**4 次工具调用、0 错误、0 重试**：start_session → present_widget → read_file → patch_file(capture + completion)。MCP 握手确认协议 2025-11-25、19 个工具。日志工具耗时分别 30 / 34 / 8 / 76 ms；整轮约 31.9 秒，主要是 5 次模型请求（含最终回复），不是 MCP 网络时间。

该轮服务端 usage：input 116,233、output 5,204、cache read 112,768 Token。它们是整轮累计值，包含 ZCode 自己的系统说明和其他工具，不能当作 PenEcho 单次 prompt 大小。该配置是文本模型，截图不进入模型视觉输入；像素和按钮交互由主任务使用真实浏览器另行核验。

内置 PenEcho Agent：同一 DeepSeek Flash 连接，**3 次工具调用**完成创建→读取→patch+done。界面确认版本 B；真实按钮点击、Undo/Redo通过。

测试中另发现并修复：源码 patch 回执缺少顶层 objectId，导致组合截图退回整个 viewport，遇到尚未就绪的 Widget 时多一次截图往返。现在返回准确对象并复用 Widget 等待/截图路径；修复后最终 ZCode 4 次调用一次通过。

ZCode 测试隔离过程也记录了两项环境问题：help 列出的 --settings 等参数实际上不被安装版 parser 接受；用户全局同名 MCP 配置覆盖项目配置。最终用仅在测试子进程内生效的 home 路径隔离及规范化真实路径解决，没有修改用户全局配置。早期连到旧服务的结果不计入新版验收，也不用于模型加速对比。
